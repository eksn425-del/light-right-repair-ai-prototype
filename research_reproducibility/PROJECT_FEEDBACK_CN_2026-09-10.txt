一、这份反馈文档的用途

这份文档用于把本轮项目复审、代码优化、真实实验、GitHub 推送状态和论文写作边界交接给网页端 AI。网页端 AI 应以本文件、HANDOFF_TO_CHATGPT.md、PAPER_NUMBERS.csv 和 CLAIMS_LEDGER.csv 为事实入口，不要根据旧论文或旧网页中的绝对值自行补写新的结论。

本轮工作目标不是重新发明项目方向，也不是立刻完成论文终稿，而是把已有的建筑学问题整理成可复现、可审计、可继续扩展的研究工程：

调研与几何核对 → 统一建筑数据 → 2.5D 候选筛选 → HB-Radiance 复核 → 独立样本验证 → 设计转译判断 → 论文图表与数字台账。

二、项目当前的正确定位

项目不应再被表述为“AI 比人工设计更好”，也不应被表述为一个已经训练完成的黑盒机器学习模型。

当前更准确的定位是：

一个面向旧街区光环境修复的规则驱动、可解释、有人在环的空间决策支持流程。它把 CAD/OBJ/CSV 数据、建筑干预规则、太阳可达性诊断、候选方案排序和高保真复核连接起来，帮助设计团队缩小方案搜索范围，并为人工设计提供可追溯的量化证据。

算法 A、B、C 的当前对应关系：

A：诊断层。使用统一后的建筑边界、高度和地面传感点，计算冬至日直射太阳小时数，定位低日照区域。

B：候选层。在符合规则的建筑对上进行双建筑组合枚举和减高候选排序，目标同时考虑低日照面积下降、平均日照增益和干预体量。

C：验证层。对筛出的候选调用 Honeybee/Radiance 进行高保真复核，再对设计转译后的体量检查恶化点、新增低日照区和指标变化。

三、本轮实际使用的数据与实验口径

1. 数据对象

当前研究对象是指定的沿湖休闲片区，不再混入其他组的片区。

2. 建筑数据

规范化建筑表共有 45 条建筑记录。当前实验规则为：movable=true、protected=false、height_m>3m。按此规则得到 36 栋可进入候选搜索的建筑。

3. 候选空间

当前 B 层使用无序双建筑组合，共 630 个候选，即 C(36,2)=630。这个“630”是当前定义下的候选宇宙，不等于 630 个方案都已经经过高保真 Radiance 模拟。

4. 太阳与网格口径

地点参数为厦门区域的纬度/经度设置；日期为冬至日；时间范围为 08:15—15:45；采样间隔为 30 分钟；地面网格为 3m；传感器高度为 0.1m；固定传感点数量为 2031。

5. 高保真复核范围

23 个规则候选完成 HB-Radiance 合并复核；另有 3 个设计转译场景和其他初始支撑场景，合并结果文件共 31 条场景记录。另行冻结并完成 20 个独立样本验证。运行记录中共有 53 个 HB 场景调用。

四、真实复现实验结果

以下数字均来自 clean run：baseline_20260909_clean，不是人工估计，也不是论文草稿中的手工抄录。

1. 数据与候选数量

总建筑记录：45
符合当前候选规则的建筑：36
2.5D 双建筑候选：630
固定传感点：2031
高保真规则候选：23
独立验证样本：20

2. 2.5D 与 HB-Radiance 的关系

23 个经筛选的规则候选上，2.5D 排名与 HB-Radiance 排名的 Spearman 相关系数为 0.883399。

在预先冻结的 20 个独立样本上：

Spearman rho：0.997668
Pearson r：0.999623
低日照面积下降 MAE：0.45m²
低日照面积下降中位绝对误差：0m²
改善方向一致率：1.0
Top-3 召回率：1.0
Top-5 召回率：0.8
Top-10 召回率：1.0

这些指标只适用于当前数据、当前几何族、当前低日照面积指标和冻结样本，不能外推为任意街区的普遍准确率。

3. 设计转译结果

C9,C15：设计转译后低日照面积下降指标为 342m²，未观察到新增低日照区或恶化点。在论文中只能写“在本次复算口径下表现为正向候选，仍需建筑设计复核”。

C9,C24：规则模型低日照面积下降为 396m²，设计转译后为 342m²；设计转译出现 4 个恶化点和 9m² 新增低日照区。因此应作为“高收益但需要人工复核的权衡候选”，不能直接称为最终最优方案。

C13,C24：设计转译仍有不利信号，不应作为自动推荐结论。

C6,C33、C9,C13：保留为证据候选和比较对象，不把它们写成跨场地通用答案。

4. 运行时间与权重敏感性

3 次隔离运行的 630 候选 2.5D 筛选中位时间约为 52.33 秒。
已完成 HB 场景的单场景中位时间约为 51.11 秒。
将单场景中位时间乘以 630 得到的全量 HB 时间约 32197 秒，但这是外推值，不是实际完成的 630 场景运行。

5 组确定性权重设置的最低 Spearman 相关系数为 0.9790，最低 Top-10 重叠数为 6/10。说明当前排序对适度权重扰动总体较稳定，但不能说排序完全不受权重影响。

五、代码和工程做了什么优化

1. 将研究运行与旧的公开 toy/demo 工程分开，建立独立研究仓库。

2. 所有核心运行目录、配置、实验输出和阶段 metadata 改为使用 pathlib 和 run_dir，不再依赖旧电脑的绝对路径。

3. 将太阳、网格、低日照阈值、建筑高度下限、减高上限、随机种子和设计候选对放入 configs/research.yaml。

4. 对 movable、protected 等字段采用严格布尔解析，避免字符串“False”被错误当作 True。

5. 新增输入格式验证：建筑字段、边界、候选数量、候选唯一性、传感点唯一性、HB 规则候选数量都自动检查。

6. 新增独立验证样本冻结流程。样本先固定并写入哈希，再执行 HB，避免事后挑选样本造成评价偏差。

7. 新增运行时间基准和权重敏感性分析。

8. 新增 8 张 320dpi 论文支持图，并由脚本根据当前 CSV 和 Radiance 原始结果自动生成。

9. 新增 PAPER_NUMBERS.csv 数字台账，记录每个论文数字的来源文件、字段、run_id 和状态。

10. 新增 CLAIMS_LEDGER.csv 主张台账，区分可以写、需要限定范围写、禁止写的表述。

11. 对 clean run 与六月历史核心结果做差异审计。120 候选、131 HB 合并和 132 已复核排名三个核心文件的行数和数值差异均为 0。

七、网页端 AI 的推荐阅读顺序

第一步：阅读本反馈文档和 GitHub 中的 PUBLIC_RESEARCH_NOTE.md。

第二步：阅读 HANDOFF_TO_CHATGPT.md，确认当前研究边界和已完成工作。

第三步：阅读 PAPER_NUMBERS.csv，所有论文数字只从这里取。

第四步：阅读 CLAIMS_LEDGER.csv，避免把有限样本结果扩写成普遍结论。

第五步：查看 scripts、src/legacy_route_b 和 configs/research.yaml，理解代码的真实逻辑。

第六步：如需写论文，再查看 TABLE_INDEX.md、FIGURE_INDEX.md 和对应结果 CSV。

网页端 AI 不应直接使用六月旧论文中的结论覆盖本 clean run，也不应自行生成新的“最终推荐方案”。如果需要新增结论，必须先指出所依据的 CSV、字段、实验范围和是否经过 HB 复核。

八、目前不能写成论文结论的内容

不能写：AI 优于人工设计。
不能写：算法对任意 OBJ 都能正确优化。
不能写：630 个候选全部完成高保真 Radiance。
不能写：系统已经证明方案安全、可施工、符合法规或通过历史保护审查。
不能写：当前 rho=0.997668 就代表系统具有 99.7% 的准确率。
不能写：C9,C15 在现实场地中绝对安全或全局最优。

可以写：

在当前规范化数据和候选规则下，系统完成了 630 个双建筑候选的 2.5D 筛选。
在冻结的 20 个独立样本上，2.5D 与 HB-Radiance 的排序和低日照面积变化方向具有较高一致性。
HB-Radiance 被用作选择性高保真复核层，而非 630 个候选的全量模拟器。
设计转译结果仍需要建筑师对空间、结构、通行、风貌和实施条件进行人工复核。

九、后续论文与实验建议

1. 先用数字台账和当前 8 张自动图完成方法、实验设置和结果章节，不要修改 clean run 的原始数值。

2. 若论文需要更强的稳健性证据，应扩大独立样本，而不是只重复当前 20 个样本。

3. 继续补 2m/3m 网格敏感性实验，并报告网格变化对候选排序和低日照面积的影响。

4. 设计组确认 C9,C15、C9,C24 等设计转译是否符合真实空间意图后，再进行最终一轮同口径 HB 复核。

5. 人工方案可以作为设计背景或案例参照，但不必设置成“AI 与人工谁更好”的竞赛。论文主线应是不同算法策略、约束和验证层级的比较。

6. 论文写作时把方法局限性写清楚：当前几何是规范化体块，低成本筛选是 2.5D，HB 复核为选择性样本，结构/产权/法规仍不在自动判断范围内。

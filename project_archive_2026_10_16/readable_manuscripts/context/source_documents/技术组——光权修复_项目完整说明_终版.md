LIGHT EQUITY RESTORATION

光权修复

AI辅助空间决策系统  ·  项目完整说明

场地：厦门灌口老街  ·  通用框架，可迁移至任意城中村  ·  2026.04

一、项目是干嘛的

城中村的老街有一个很普遍的问题：楼与楼之间靠得太近，底层的住户和店铺几乎全天晒不到阳光。传统的解决方法要么是「大拆大建」（破坏社区、成本极高），要么是「靠设计师感觉」（没有数据支撑，经常顾此失彼——比如为了引入阳光加了一座高空连桥，结果老人小孩根本走不上去）。

这个项目要做的事情是：用算法代替「感觉」，精确计算出「改哪里、改多少、怎么改」，在动最少的前提下让底层街道获得尽可能多的阳光，同时保证改完之后老人、孩子走在街上是安全的。

一句话概括

在不拆建筑的前提下，用算法找到「改动最小、采光提升最大、且对所有人安全」的城中村微更新方案，并用改造前后的数据对比实验来证明这套算法比人工设计更有效。

这个项目体现了什么价值

人文关怀：「光照权」是每个底层居民应有的基本权利，算法为弱势群体（老人、残障人士）优先保障安全通行。

绿色可持续：不拆不建（或极少量新建），最小物理干预，减少建筑垃圾和碳排放，是真正意义上的可持续更新。

计算机与建筑交叉：用AI和算法取代「经验直觉」，让设计决策变得可量化、可验证、可复现——这是计算设计领域的前沿方向。

普适性：以灌口老街为第一个实验场，但整套算法框架适用于任意高密度老街或城中村，换一个.obj文件就能跑。

三、算法A · 诊断层——找病灶

算法A回答一个问题：这条街上，哪里最暗，为什么暗，能从哪里漏进阳光？

输入

建筑组导出的灌口老街SU白模（一个.obj文件，整条街建筑体量）

厦门的经纬度（24.5°N）+ 冬至日太阳轨迹数据（用最不利情况：阴影最长的那天来测试）

算法内部怎么运行

用Minecraft的逻辑来想象：Python先把整个街道变成无数个1米×1米×1米的小格子——建筑占据的格子标为「实体」，建筑外面的空格子标为「空气」。这叫「体素化」。

然后模拟太阳从冬至日早8点到下午4点的运动轨迹，每小时往格子矩阵里发射光线，看哪些「空气格子」被照到了、哪些没有。累计计算每个地面格子在一整天里被太阳照到的时间（单位：小时）。

输出（说人话）

一张「采光热力图」（PNG图片）：颜色越深代表这个位置一天内晒到的太阳越少。一眼就能看出「哪段最暗」。这是论文里最直观的图之一。

一个「可改善缝隙列表」（CSV文件）：标出哪几处建筑之间的缝隙，如果稍微打开就能让阳光漏进来，告诉算法B「重点看这几个位置」。

建筑组需要配合的事（只有一件）

拿到热力图之后，史天一对照现场感受确认一下：「图上标红的这几段，是不是你们现场觉得最阴暗的地方？」如果对得上，说明白模数据准确，可以继续跑算法B；如果对不上，说明某处尺寸偏差大，修正白模。

四、算法B · 决策层——找最优改法

算法A告诉我们哪里暗。算法B回答：改哪里、怎么改，动作最小但效果最好？

输入

算法A的输出（暗区坐标 + 可改善缝隙列表），自动传入，不需要人工操作

一条规则：「不能动建筑的承重墙和主体结构」（由史天一标注哪些区域是不可动的）

算法能做的三类操作

操作类型

具体是什么

举例

减法

在建筑上做小切除：去掉违建突出部分，或把某个角切掉一点（退台）

把某楼角的一个2×2×3米的突出部分切掉，阳光从这个缺口照进来

加法

在两栋楼的缝隙处插入一个小体块

在两楼之间插一个半透明的采光井或小平台，把光引下来的同时增加公共空间

重组

把已有的废弃空间打通

把底层堆放杂物的门廊打通，变成可通行的灰空间，同时让光能穿过

寻优过程（模拟退火，说人话）

想象你在做一个很复杂的乐高：在这条街上随机组合上面三类操作，算一下这种改法的总分是多少。总分公式是：

总分 = 居住采光提升 + 街道采光提升 — 改动的建筑体积（动的越少越好） — 新产生的遮挡

分数高 = 阳光改善得多、动的少、没产生新的阴影。

算法会在计算机里把这个过程重复几万次，每次都在「高分方向」上微调，最终收敛到一个「很难再提高了」的状态，这就是最优方案。

为什么输出2-3个而不是1个：因为「采光最优」不等于「对人最安全」。比如第1名的方案采光分数最高，但它建议在高处加一个没有护栏的平台，老人走不了。所以B给出前几名候选，让算法C来做安全筛选。

输出

2-3组候选改造方案，每组包含：「在哪个坐标削掉多少」「在哪个坐标加一个多大的体块」（输出为.obj文件，可以直接拖进SU对照）

每组方案的得分数据表（CSV）：各指标分项得分，让人清楚地看到每个方案的优劣权衡

五、算法C · 验证层——确保每个人都能安全走

算法B找到的是「采光最优」方案，不是「对人最友好」的方案。算法C专门回答：按这个方案改了之后，老人、小孩、坐轮椅的人走在这条街上，安不安全？

输入

算法B输出的2-3组候选改造方案（坐标集），自动传入

两步走逻辑

第一步：先筛掉不安全的。在改造后的街道里，把所有可能走的路径都找出来，逐条过滤：

坡度超过8% → 不能走（轮椅无法通行）

台阶高度超过16厘米 → 不推荐（老人难迈步）

通道净宽不足1.2米 → 不能走（两人无法并行，轮椅过不去）

超过1米高的地方没有护栏 → 不能走

以上任何一条违反，这条路直接标「死路」

第二步：在安全路径里找最好的。所有通过了第一步的路径里，选采光时间最长、绕路最短的那条，作为推荐路线。

注意：连桥不是必须走的。算法C会比较「走连桥」和「走地面」哪个更安全更亮——只有连桥更安全时才推荐连桥，否则推荐地面路。

输出

从B的2-3个候选里选出最终推荐方案（采光好+安全通过率最高的那个）

「安全可达覆盖率」：改造后这条街有多少比例的区域对老人安全可达（目标≥80%）。这个数字是论文核心数据之一。

「最终方案完整数据集」（CSV）：包含改造前/改造后的所有量化指标对比

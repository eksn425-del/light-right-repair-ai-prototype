# 光权修复项目：干预等级表填写说明

更新时间：2026-06-01

## 1. 这张表的作用

`intervention_levels_template.csv` 不是为了让 AI 自己判断哪些建筑能拆、哪些不能拆。它的作用是把建筑组的现场判断、任务书要求、产权/功能/风貌限制，转成算法能读懂的约束。

也就是说：

- 人负责判断：建筑功能、产权风险、风貌价值、公共服务属性、现场可改性。
- AI 负责计算：哪些体块遮光更严重、哪种小干预可能改善采光、候选方案的指标如何变化。
- 最终设计仍由人审核：算法输出是“候选建议”，不是施工决定。

## 3. 字段解释

| 字段 | 建筑组怎么填 |
| --- | --- |
| building_id | 建筑编号，例如 C25、C42，不要改。 |
| name | 可不填，也可以写常用名称。 |
| height_m | 当前算法识别高度，不建议随便改；若发现明显错误，在 notes 里说明。 |
| current_function | 当前功能，如住宅、幼儿园、闲置公房、旧菜市场、商铺、空置等。 |
| heritage_value | 风貌/历史价值：high / medium / low / unknown。 |
| public_service | 是否公共服务建筑：yes / no / unknown。幼儿园、社区服务、卫生点等填 yes。 |
| vacancy_or_low_efficiency | 是否闲置或低效使用：yes / no / unknown。 |
| structure_or_property_risk | 结构或产权风险：high / medium / low / unknown。 |
| intervention_level | 干预等级，填 0-4。 |
| allowed_operations | 允许操作，用英文分号分隔，例如 `facade_update;ground_floor_opening`。 |
| intervention_reason | 为什么这样定级，用短句说明。 |
| confidence | 判断可靠度：confirmed / likely / to_check / algorithm_suggested_pending_field_check。 |
| field_checker | 填写人或复核人。 |
| notes | 其他备注。 |

## 4. 干预等级定义

| 等级 | 名称 | 含义 | 典型允许操作 |
| --- | --- | --- | --- |
| 0 | 不可动 | 不允许算法直接修改体块 | `none` |
| 1 | 限制干预 | 只允许外立面、功能激活、室内更新，不动主体体量 | `facade_update;function_activation_only` |
| 2 | 轻度干预 | 可做底层灰空间整理、小尺度打开、局部公共设施插入 | `ground_floor_opening;gray_space_reorganize;small_addition` |
| 3 | 中度干预 | 可做局部退台、削减角部、开采光缝，但需人工复核 | `subtract;step_back;light_well;partial_opening` |
| 4 | 重点干预 | 闲置、低效、可更新价值高，可作为主要改造对象 | `key_renewal;function_replacement;mass_reorganization;public_space_insertion` |

## 5. 目前已知约束

- C42 已确认为幼儿园，属于公共服务建筑，当前表格预填为 0 级不可动。
- 当前片区暂无已确认保护建筑。
- C24、C26、C33 是算法第一轮识别出的遮挡贡献对象，表格中暂定为 3 级中度干预候选，但必须由建筑组复核其功能、产权、风貌和结构风险。
- 其他建筑目前仍是 `to_check`，不能直接当作“随便可改”。

## 6. 判断原则

优先不可动或限制干预：

- 幼儿园、社区服务、卫生、养老等公共服务设施。
- 有明确历史风貌价值、闽南特色构件或街巷记忆价值的建筑。
- 产权复杂、住户密集、结构风险高的建筑。
- 位于消防、道路安全、重要出入口控制位置的建筑。

优先纳入可干预：

- 闲置旧菜市场、闲置公房、闲置空地、低效附属空间。
- 遮挡贡献明显、但功能和风貌风险较低的建筑。
- 底层灰空间、废弃夹缝、可整理边角空间。
- 对慢行、公共空间和采光改善同时有价值的节点。

## 7. 给组员的最小任务

每栋建筑至少补齐四项：

1. `current_function`
2. `public_service`
3. `intervention_level`
4. `intervention_reason`

如果时间够，再补充：

1. `heritage_value`
2. `vacancy_or_low_efficiency`
3. `structure_or_property_risk`
4. `allowed_operations`

表格填完后，算法就可以从“所有可动”升级为“按人工约束进行可复核优化”。

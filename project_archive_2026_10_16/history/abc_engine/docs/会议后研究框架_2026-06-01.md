# 会议后研究框架：光权修复 AI 辅助空间决策系统

更新时间：2026-06-01

## 1. 研究方向调整

会议后建议把项目重点从“AI 方案与人工方案谁更好”调整为：

> 在旧街区更新中，如何通过人工设定干预边界 + AI 采光诊断与多轮候选生成，形成一套可复核、可解释、低成本的最小干预光环境优化流程。

这个方向更稳，因为人工方案不是固定标准，不适合作为唯一对照组。更合理的对照是：

- 改造前 baseline；
- 算法第 1 轮候选；
- 加入人工干预等级表后的算法第 2 轮候选；
- 最终由人审查后的推荐方案。

## 2. 项目边界

当前阶段聚焦沿湖休闲片区，不再等待其他组片区。

核心问题：

- 哪些地方采光不足；
- 哪些建筑或缝隙对暗区影响较大；
- 在最小干预原则下，哪些体块调整最值得被讨论；
- 干预是否违反幼儿园、公共服务、风貌、道路和安全边界。

当前不把项目扩展为：

- Web 平台；
- 数字孪生系统；
- Rhino / Grasshopper / Ladybug 强依赖流程；
- 施工级日照审查工具。

## 3. ABC 流程的论文表达

### 算法 A：诊断层

输入 CAD/SU 转换后的建筑体块、道路、节点和约束表，基于厦门冬至日 8:00-16:00 的太阳位置进行简化 2.5D 遮挡判断。

输出：

- 采光小时数热力图；
- 暗区 CSV；
- 建筑遮挡贡献或可改善缝隙；
- baseline 指标。

### 算法 B：决策层

在人工设定的干预等级约束内生成候选方案。候选不是最终设计，而是“值得设计组讨论的体块调整建议”。

干预类型：

- 减法：退台、局部削减、打开采光缺口；
- 加法：小型平台、灰空间设施、公共节点；
- 重组：底层灰空间打通、闲置空间功能置换。

### 算法 C：验证层

对候选方案进行约束复核。当前 C 层建议作为辅助验证，不作为论文主结论。

验证内容：

- 是否触碰不可动建筑；
- 是否触碰保护或公共服务边界；
- 是否造成明显道路/慢行风险；
- 是否满足基础安全可达指标。

## 4. 核心指标

建议论文主指标保留 5 个：

| 指标 | 用途 |
| --- | --- |
| average_sunlight_hours | 平均采光小时数，表示整体改善。 |
| dark_zone_ratio | 暗区比例，表示问题面积是否减少。 |
| severe_dark_zone_count | 严重暗区数量，表示最差区域是否被缓解。 |
| intervention_volume | 干预体积，体现最小干预原则。 |
| changed_building_count | 涉及建筑数量，体现方案复杂度。 |

辅助指标：

- protected_conflict_count；
- public_service_conflict_count；
- accessible_route_ratio；
- safety_score。

## 5. 迭代路线

### Iteration 0：现状基线

使用现有 OBJ / DXF / CSV 跑出真实片区 baseline。这个结果作为论文里“现状采光问题”的依据。

### Iteration 1：算法初筛

在当前“C42 不可动、其余暂可动”的条件下跑出第一轮候选。这个结果只用于发现算法倾向和问题，不作为最终方案。

### Iteration 2：加入人工干预等级表

建筑组填写 `intervention_levels_checked.csv` 后，算法重新筛选。此轮开始才适合作为正式研究结果。

### Iteration 3：权重敏感性测试

调整权重，比较“采光优先”“最小干预优先”“安全约束优先”三种策略下候选是否稳定。

### Iteration 4：人工方案吸收

不再把人工方案作为日照竞争对象，而是把人工方案中的功能置换、公共节点、慢行意图转成算法约束或候选操作，再做复核。

## 6. 人工与 AI 分工

建筑组需要做：

- 填干预等级表；
- 确认每栋建筑功能、是否公共服务、是否闲置；
- 标注不可动、限制干预和重点可改对象；
- 对算法建议进行设计转译；
- 最终用人工判断修正方案表达。

Codex/算法需要做：

- 读取真实数据；
- 运行 A/B/C 流程；
- 按干预等级过滤候选；
- 输出图表、CSV、OBJ 和指标；
- 生成论文可用的结果说明；
- 做权重敏感性和多轮对比。

## 7. 下一步优先级

1. 当前先采用官方确认口径：C42 幼儿园为 0 级不可动，其余建筑作为 3 级中度可干预候选。
2. 算法接入 `intervention_levels_checked.csv`，禁止对 0 级建筑做体块修改。
3. 重新运行沿湖休闲片区 ABC，并输出保守、均衡、采光优先三类候选。
4. 输出第 2 轮结果：热力图、候选体块图、指标对比、最终推荐说明。
5. 后续如果组员补充更细的功能/产权/风貌判断，再覆盖当前默认口径重新运行。

## 8. 当前可以对老师说明的话

本项目不是让 AI 取代建筑设计判断，而是把旧街区中“哪里暗、哪里能改、改多少、是否越界”转化为一套可复核的数据流程。人工负责定义价值边界与改造等级，AI 负责在边界内做采光诊断和候选筛选，最终输出供设计组讨论和论文表达的最小干预方案。

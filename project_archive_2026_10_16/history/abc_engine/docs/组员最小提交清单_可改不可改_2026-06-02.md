# 组员最小提交清单：可改 / 不可改建筑

更新时间：2026-06-02

## 1. 他们最少给什么

当前组员已经确认：任务书或官方资料没有逐栋指定哪些可改、哪些不可改；唯一明确不可改造对象是 C42 幼儿园。

如果后续还要更细化，组员只需要给一个列表：

| building_id | intervention_status | reason |
| --- | --- | --- |
| C42 | 不可干预 | 幼儿园，公共服务建筑 |
| C24 | 可干预 | 闲置或低效空间，可作为采光优化候选 |
| C26 | 可干预 | 可局部退台，需复核结构与功能 |

在当前阶段，这已经足够启动新的算法测试。我们已先按“C42 不可干预，其余建筑作为算法候选”生成默认约束表。

## 2. 更推荐的提交格式

建议多给一列 `intervention_level`：

| building_id | intervention_status | intervention_level | reason |
| --- | --- | --- | --- |
| C42 | 不可干预 | 0 | 幼儿园，公共服务建筑 |
| C24 | 可干预 | 3 | 可局部削减或退台 |
| C26 | 可干预 | 2 | 只允许底层灰空间整理 |

## 3. 等级含义

| 等级 | 含义 |
| --- | --- |
| 0 | 不可干预，算法不能动 |
| 1 | 只能立面或功能更新，不动体块 |
| 2 | 轻度干预，可做底层、灰空间、小设施 |
| 3 | 中度干预，可局部削减、退台、开采光缝 |
| 4 | 重点可改，可作为主要更新对象 |

## 4. 不可干预原因怎么写

常见原因：

- 幼儿园、社区服务等公共服务建筑；
- 有历史风貌或街区记忆价值；
- 产权复杂；
- 结构风险高；
- 任务书要求保留；
- 影响消防、道路、安全或重要出入口；
- 老师或组员现场判断不适合动。

## 5. 可干预原因怎么写

常见原因：

- 闲置旧菜市场；
- 闲置公房；
- 闲置空地；
- 低效附属建筑；
- 遮挡贡献明显；
- 对慢行、公共空间和采光改善有潜力；
- 可通过局部退台、打开底层、灰空间整理实现低成本更新。

## 6. 给组员的直接话术

你们不需要重新建一套复杂表格。先按 C1-C45 每栋建筑判断：

- 这栋能不能动？
- 如果不能动，为什么？
- 如果能动，大概能动到什么程度？

把结果发成 Excel 或 CSV 就行。后续我会把它转换成算法能读的 `intervention_levels_checked.csv`，再重新运行保守、均衡、采光优先三版 AI 候选。
